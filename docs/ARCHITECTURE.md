# Как устроен SaqtaDauys

[← На главную](../README.md) · [Сценарий демонстрации](DEMO.md)

У проекта три точки входа: пакетная маршрутизация, текстовый чат и Telegram.
Оба чата используют один диалоговый движок; голосовой канал добавляет распознавание
и озвучивание к тому же разговору.

## Путь одной реплики

1. Telegram получает текст или завершённую голосовую запись. Проверяются тип чата,
   доступ пользователя и размер сообщения.
2. Голос преобразуется в текст. При ожидании телефона или ИИН используется
   `gpt-4o-transcribe` с подсказкой о диктовке цифр; обычно — `gpt-4o-mini-transcribe`.
3. Движок локально обрабатывает приветствие, команды управления и однозначный
   ввод ожидаемого идентификатора.
4. LLM определяет язык, тип реплики и поля. Для каждого извлечённого значения
   требуется цитата из текущего сообщения; Python проверяет её и формат поля.
5. Маршрутизатор выбирает сценарий. Движок сохраняет другие просьбы в очереди,
   учитывает срочность и при необходимости откладывает текущую задачу.
6. Обработчик уточняет недостающие данные, находит клиента и полис, получает факты
   или подготавливает действие для подтверждения.
7. Ответ отправляется текстом и, если включено, голосом. Трассировка показывает
   выбранные сценарии, действия и время каждого этапа.

Маршрутизатор использует **`gpt-4o-mini`**, температуру **0.1** и JSON mode.
В `predict_intent()` проверяются структура ответа и допустимые ID; при ошибке
возвращается `SYS_UNCLEAR`. Эталонные ответы `expected` и ID тестовых реплик
модели не передаются. Понимание диалоговой реплики использует отдельную строгую JSON-схему.

## Состояние и подтверждения

У каждой задачи собственные поля. Короткая история помогает понять контекст,
но новые значения принимаются с подтверждением из текущей реплики.
Телефоны и ИИН, уже записанные цифрами, разбираются локально с сохранением нулей.
Неполный номер не дополняется предположениями.

Перед действием, требующим согласия, движок сохраняет конкретную операцию и её
параметры в `PendingAction`. Явное подтверждение выполняет именно эту операцию.
Исправление данных или ошибка отменяет прежнее подтверждение и требует нового
согласования. Повторное «да» после завершения не должно создавать вторую запись.
Сбой загрузки голосового сообщения и слишком длинная реплика тоже снимают
подтверждение: движок не должен выполнять прежнюю операцию после непрочитанного исправления.

Передача оператору имеет отдельное состояние. Ответ «да, подключайте» не запускает
снова отложенную задачу. Возврат к ней требует явной просьбы. Передача учебная:
живого оператора за ботом нет, и бот сообщает об этом пользователю.

## Данные и исполнение

Учебная дата **2026-10-01** задаётся датасетом. Каждый сеанс получает отдельную
копию mock backend; исходные JSON-файлы остаются неизменными. `/reset`, перезапуск
процесса или час бездействия сбрасывают данные разговора.

Для 33 бизнес-сценариев есть обработчики. У `SC02`, `SC04`, `SC05`, `SC06`, `SC12`,
`SC27`, `SC28` самостоятельного исполнения нет: используется учебная передача
оператору. Наличие обработчика не означает реализацию всей цепочки действий из ТЗ.
Например, консультация и расчёт КАСКО не оформляют настоящий полис.
Поля для расчёта запрашиваются с учётом контракта действия: франшиза нужна
для расчёта КАСКО, хотя в сценарии консультации она отмечена как необязательная.
Для вопроса об оплате конкретного продукта модель получает его условия рассрочки.

В исходных данных нет расписания клиник, поэтому для демо используются часы
10:00, 11:00, 14:00 и 16:00 по рабочим дням. Идентификация по телефону упрощена
для кейса; реальные SMS, email и переводы звонков не отправляются.

## Голосовой канал и хранение

- Обрабатываются личные чаты, до 64 активных сеансов в одном процессе.
- Сообщения проходят последовательно. Голосовая запись ограничена 60 секундами
  и 10 МБ, текст — 4000 символами.
- Аудио обрабатывается в памяти. В `.runtime/` хранится только номер обновления
  Telegram, без текста, аудио и ключей.
- Этот номер записывается **до обработки**: после перезапуска действие не должно
  повториться. Если процесс остановился посередине ответа, реплику нужно отправить заново.
- `total_processing` включает обработку и отправку ответов. Это не измерение
  времени до первого звука на устройстве пользователя.

Реплики, короткая история и голос отправляются в OpenAI для обработки; сообщения
остаются в самом Telegram-чате. Типовые телефоны, ИИН и email маскируются
в ответах и трассировках, но это не универсальный фильтр персональных данных.
Для публичного показа используются вымышленные клиенты из `/demo`.

## Работа с кодом

Настройки стиля находятся в [`pyproject.toml`](../pyproject.toml): Ruff,
единое оформление импортов и строк, целевая версия Python 3.10.

```bash
python -m pip install -r requirements-dev.txt
ruff check src tests
ruff format --check src tests
python -m unittest discover -s tests -v
```

Применить форматирование: `ruff format src tests`. Для автоматического исправления
простых замечаний: `ruff check --fix src tests`.

Локальные тесты подменяют API и проверяют контракты, состояние и действия.
Они не измеряют качество живого LLM-диалога. В свободных прогонах замечены ошибки
выбора суммы из нескольких чисел, языка ответа и продолжения разговора после расчёта;
этим случаям нужны отдельные проверки и доработка.
