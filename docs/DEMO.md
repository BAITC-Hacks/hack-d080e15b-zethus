# Демо SaqtaDauys за 3–4 минуты

[← На главную](../README.md)

Цель показа — провести один понятный разговор: клиент просит помощь, бот выбирает
сценарий, уточняет данные и выполняет учебное действие после подтверждения.

## Перед выступлением

1. Обновите зависимости: `python -m pip install -r requirements.txt`.
   Запустите **`python src/web_demo.py`** и откройте **http://localhost:8000**.
2. Разрешите микрофон, проверьте звук и громкость. Нажмите «Говорить», произнесите
   «Здравствуйте», затем «Стоп». Если браузер блокирует звук, нажмите ▶.
3. Нажмите «Новый разговор». Учебные телефоны показаны под чатом;
   для записи к врачу понадобится **+77010000002**.
4. Панель супервизора видна справа. Объяснение появляется чуть позже ответа:
   оно запрашивается в фоне. JSON текущей реплики можно скачать из панели.
5. Откройте второй терминал для оценки сохранённых предсказаний:

   ```bash
   python data/evaluate.py predictions.json data/dev_utterances.json
   ```

После изменений в коде перезапустите процесс. Отправляйте следующую реплику,
когда бот закончит отвечать. Для нескольких независимых проверок нажимайте
«Новый разговор». Не используйте личные номера вместо учебных.

Telegram остаётся дополнительным каналом: `python src/telegram_bot.py` показывает
QR и ссылку текущего бота. Там доступны `/reset`, `/demo`, `/trace_on`.
По обязательному условию PDF голосовое взаимодействие нужно показать и в вебе.

## 1. Объяснить идею · 20 секунд

> Клиенту не нужно подбирать слова под меню робота. Он может говорить по-русски,
> по-казахски и задавать несколько вопросов. LLM выбирает сценарий и извлекает
> данные из речи, а Python проверяет поля и управляет действиями.
> Показываем разговор через микрофон браузера, рядом — выбор сценария и его объяснение.

## 2. Записаться к врачу · 1–2 минуты

| Что отправить | На что обратить внимание |
|---|---|
| «Здравствуйте» | Бот начинает разговор. |
| «Хочу записаться к лору завтра в Астане по ДМС» | Выбирает запись к врачу и запрашивает недостающие данные. |
| `+77010000002` | Находит учебного клиента с полисом ДМС Comfort и предлагает приём. |
| «Да» — после предложения подтвердить | Создаёт запись в памяти сеанса и сообщает результат. |

В датасете зафиксировано **1 октября 2026 года**. Поэтому «завтра» в демо —
**2 октября 2026 года**. Бот использует учебные часы приёма, а не живое расписание клиники.

Покажите, что предложение записи и её подтверждение — два отдельных шага.
В панели найдите сценарий `SC21`, ожидаемое подтверждение и действие записи.

## 3. Сменить тему · 40 секунд

Этот вариант удобно показать **до подтверждения записи**:

1. Спросите: «А сначала скажите адрес офиса в Алматы».
2. Получите ответ и попросите: «Вернёмся к записи к врачу».
3. Проверьте, что бот вернулся к незавершённой задаче и снова согласовал запись.
4. Ответьте «Отмена», чтобы показать отказ от действия.

Либо покажите казахский язык отдельным коротким разговором:

Нажмите «Новый разговор», затем:

```text
ДМС полисімнің мерзімін тексеріңізші.
+77010000002
```

После сброса учебные данные и история разговора начинаются заново.

## 4. Показать результат и границы · 30 секунд

Откройте вывод оценщика: в сохранённом прогоне правильно разобраны **104 из 104**
реплик открытого dev-набора. Промпт уточнялся по этому набору, поэтому это не оценка
качества на скрытых данных и не гарантия безошибочного голосового диалога.

Скажите прямо: операции учебные, реальные полисы не оформляются, живой оператор
не подключается. В свободном разговоре ещё встречаются ошибки сумм, языка ответа
и продолжения предыдущего запроса. Их нужно проверять отдельно от маршрутизации.

## Если жюри спросит

| Вопрос | Короткий ответ |
|---|---|
| Это телефонный звонок? | Основной канал — микрофон браузера; дополнительно Telegram. Телефония и непрерывный разговор не подключены. |
| Что делает LLM? | Распознаёт речь, выбирает сценарий, извлекает поля и формулирует ответ по фактам. |
| Кто разрешает действие? | Диалоговый движок проверяет данные и ждёт явного подтверждения операции. |
| Откуда берутся полисы и цены? | Из учебных JSON-файлов и формул кейса. Изменения хранятся в памяти сеанса. |
| Выполняются все 40 бизнес-сценариев? | Для 33 есть обработчики; 7 переводятся в учебную передачу оператору. Полнота цепочек действий различается. |
| Что означает 100%? | Результат сохранённого прогона на 104 открытых репликах, использованных при доработке промпта. |
| Как измерена скорость? | Сервер измеряет стадии, браузер — начало воспроизведения. В одном полном голосовом прогоне получено 5,19 с от оценённого конца речи. Ориентир 1,5 с пока не достигнут; это бонус, не условие сдачи. |
| Откуда объяснение? | Из отдельного фонового LLM-запроса после выбора. Он не может поменять сценарий или выполнить действие. |

Запускайте независимые примеры после «Новый разговор» (`/reset` в Telegram): тогда предыдущий запрос не вмешается
в следующую демонстрацию.

Подробно: [аудит PDF](REQUIREMENTS.md) и [честные замеры задержки](LATENCY.md).

## Проверка исправленного диалога ДТП

Это учебный тест на вымышленных данных. Начните новый разговор:

```text
Здравствуйте у меня авария
да один умер
А91 Д13
```

Ожидаемый результат: после второй реплики `injured=true`, повторного вопроса
о пострадавших нет. Бот напоминает об экстренном обращении и спрашивает место;
после третьей реплики сохраняет адрес как сообщение клиента и выполняет учебную
передачу контекста. Живой оператор и экстренные службы не вызываются.

Варианты «есть. умер водитель другой» и «Жүргізуші қайтыс болды» проверены отдельно.
«Погибших нет» не равно «пострадавших нет» — бот должен уточнить наличие пострадавших.
Короткий адрес не проверяется по карте; если в сообщении есть новая просьба,
она по-прежнему проходит через LLM.

Повторить через API без Telegram (расходуется API-квота):

```bash
python src/chat_demo.py --script examples/accident_regression.json --trace
```
