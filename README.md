# hack-d080e15b-zethus
Hackathon team repository for Zethus

## Voice Router — диалоговый бот Saqta Insurance

Текстовый бот ведёт разговор на русском и казахском: выбирает сценарий, собирает
недостающие данные, ищет клиента и полис, выполняет учебные действия. Для
необратимых действий показывает условия и ждёт явного подтверждения. Смена темы
сохраняет незавершённый запрос; к нему можно вернуться после нового вопроса.

Запуск чата после настройки `.env` и зависимостей:

```bash
python src/chat_demo.py
```

Для демонстрации выбранных сценариев, полей и действий используйте
`python src/chat_demo.py --trace`. Команды внутри чата: `/reset` — новый сеанс с
исходными данными, `/state` — текущее состояние, `/quit` — выход.

## Голосовое демо в Telegram

1. Откройте [@BotFather](https://t.me/BotFather), отправьте `/newbot`, задайте имя
   и username бота. Скопируйте выданный токен в **существующий** `.env` в корне проекта:

   ```dotenv
   OPENAI_API_KEY=ваш_существующий_ключ_OpenAI
   TELEGRAM_BOT_TOKEN=токен_от_BotFather
   TELEGRAM_ALLOWED_USER_IDS=
   ```

2. Запустите из корня проекта:

   ```bash
   source .venv/bin/activate
   python src/telegram_bot.py
   ```

3. Откройте своего бота в Telegram, нажмите **Start** и отправьте голосовое
   сообщение: «Здравствуйте». Затем: «Хочу записаться к лору завтра в Астане по ДМС».
   На запрос телефона можно ответить текстом `+77010000002`; запись подтвердите «да».

Бот сначала показывает распознанную реплику, затем отвечает текстом и голосовым
сообщением. При сбое озвучивания текстовый ответ остаётся доступен. Используются
`gpt-4o-mini-transcribe` → диалоговый движок с `gpt-4o-mini` → `gpt-4o-mini-tts` (голос `coral`).
Язык распознавания не фиксируется, чтобы принимать русский, казахский и смешанную речь.
Когда бот ожидает телефон или ИИН, используется `gpt-4o-transcribe` с контекстом
диктовки цифр. Это отдельная модель распознавания; модель маршрутизатора остаётся
`gpt-4o-mini`. Точность диктовки любых цифр не гарантируется: при ошибке отправьте
номер текстом. Записанные цифрами телефон и ИИН заполняются без повторного
переписывания языковой моделью. Телефон принимается в виде `+7` и 10 цифр,
с начальной `8` вместо `+7` или как 10 цифр без кода страны; пробелы и дефисы допустимы.
Неполный номер не дополняется предположениями.
Отдельные цифры и группы числительных RU/KK разбираются локально с сохранением
нулей, например «семьсот один» и «жеті жүз бір» → `701`; неизвестная запись требует уточнения.

Это обмен голосовыми сообщениями после завершения записи, не непрерывный звонок.
Домен, публичный сервер, ngrok и отдельная телефония не нужны: бот получает сообщения
через long polling, пока запущен Python. Остановка — `Ctrl+C`. Запускайте один
экземпляр на токен; для бота с существующим webhook используйте отдельного демо-бота.

Команды: `/demo`, `/reset`, `/voice_off`, `/voice_on`, `/trace_on`, `/trace_off`, `/help`, `/id`.
`/demo` показывает телефоны учебных клиентов: например, `+77010000002` для ДМС.
Ваш личный номер может отсутствовать в вымышленной базе, даже если его распознали
верно. Команда не авторизует пользователя автоматически и не меняет текущий диалог.
`/trace_on` добавляет JSON-файл с выбранными сценариями, полями, действиями и временем
распознавания, диалога и синтеза. `total_processing` включает обработку и отправку
ответов, но не измеряет время до воспроизведения на телефоне и не является метрикой
первого аудио из ТЗ.

Только личные чаты; по умолчанию демо доступно всем, кто напишет боту. Для ограничения
получите свой ID через `/id`, добавьте `TELEGRAM_ALLOWED_USER_IDS=123456789` и
перезапустите процесс. Можно перечислить ID команды через запятую.
Сеансы разных чатов изолированы и сбрасываются после часа простоя или перезапуска.
Входящая запись ограничена 60 секундами и 10 МБ. Записи обрабатываются в памяти,
локальные аудиофайлы не создаются. Telegram хранит сообщения в самом чате.
Обе API-службы используют сеть; распознавание, диалог и синтез расходуют квоту OpenAI.

В `.runtime/` сохраняется только номер полученного обновления Telegram, без ключей,
текста и аудио. Номер записывается до обработки, чтобы после сбоя не повторить действие;
при остановке посередине ответа отправьте незавершённую реплику заново.
Сообщения обрабатываются последовательно: это демо для команды, не сервер массовых звонков.

Описание API: [создание бота](https://core.telegram.org/bots/features#creating-a-new-bot),
[голосовые ответы Telegram](https://core.telegram.org/bots/api#sendvoice),
[распознавание OpenAI](https://developers.openai.com/api/docs/guides/speech-to-text),
[синтез OpenAI](https://developers.openai.com/api/docs/guides/text-to-speech).

## Проверка диалога

Действующий полис:

```text
Вы: Проверьте, действует ли мой полис ОГПО.
Вы: +77010000001
```

Бот должен сообщить срок `SQ-OGPO-104501`: `2026-03-15` — `2027-03-14`.
Если тип страховки не указан, у этого клиента бот уточнит выбор между ОГПО и КАСКО.
Для проверки просроченного полиса начните `/reset` и используйте телефон
`+77010000003`: срок его ОГПО закончился `2026-09-29`.

Запись с подтверждением:

```text
Вы: /reset
Вы: Хочу записаться к лору завтра в Астане по ДМС.
Вы: +77010000002
Вы: да
```

Бот найдёт полис ДМС Comfort, предложит приём в Saulet Medical на `2026-10-02`
и запишет только после подтверждения. «Да, но в другой день» требует нового
согласования. Повторное «да» после завершения не создаёт вторую запись.
До подтверждения можно спросить об адресе офиса; затем бот предложит вернуться к записи.

Составной запрос: «Проверьте мой полис и измените электронную почту на
demo@mail.example». После первого результата бот предложит продолжить второй
вопрос и отдельно подтвердить изменение контактов.

Повторяемый сценарий для ручной проверки, с настоящими вызовами OpenAI:

```bash
python src/chat_demo.py --script examples/chat_demo.json --trace
```

Все клиенты и примеры взяты из вымышленного датасета. Чат отправляет в OpenAI
текущие реплики и короткую историю для понимания речи. В ответах и трассировке
телефоны, ИИН и email маскируются.

## Как устроен чат

- `src/agent/state.py` — активный запрос, очередь просьб, отложенные задачи и подтверждение.
- `src/agent/catalog.py` — чтение каталога, проверка и нормализация полей.
- `src/agent/llm.py` — извлечение данных и языка через `gpt-4o-mini`, маршрутизация,
  формулирование ответов по фактам. Короткие ответы заполняют текущий сценарий.
- `src/agent/dialog_manager.py` — выбор следующего вопроса и разрешённых действий.
- `src/tools/backend.py` — поиск данных, расчёты и учебные операции.
- `src/telegram_bot.py` — личные чаты, команды и отдельный сеанс на пользователя.
- `src/tools/telegram_api.py`, `src/tools/audio.py` — получение аудио, распознавание и голосовой ответ.

Отдельное приветствие обрабатывается локально и не превращается в `SYS_GOODBYE`.
Приветствие вместе с просьбой проходит обычную маршрутизацию. При извлечении полей
модель должна привести цитату из текущей реплики; значения из прошлой реплики
отбрасываются. Длинный ответ или отсутствие ожидаемого поля дополнительно проверяются
маршрутизатором, чтобы новая просьба не затерялась внутри старого сценария.

Python проверяет принадлежность полиса клиенту и выполняет расчёты по формулам
из базы знаний. Идентификация по телефону в демо соответствует условиям кейса;
это не полноценная аутентификация для реальной страховой системы.
Учебная дата фиксирована: `2026-10-01`. «Завтра» означает `2026-10-02`.

Изменения действуют только в памяти одного сеанса. Исходные JSON-файлы не меняются,
реальные SMS, письма и переводы звонков не выполняются. В датасете нет расписания
клиник: для демонстрации используются учебные часы 10:00, 11:00, 14:00 и 16:00
по рабочим дням. Для услуг Basic, требующих направления, предусмотрен оператор.

Для `SC02`, `SC04`, `SC05`, `SC06`, `SC12`, `SC27`, `SC28` самостоятельное
исполнение пока не реализовано: бот передаёт контекст оператору в демо. Остальные
33 сценария имеют обработчики: консультации и расчёты, проверка полисов и заявлений,
запись, регистрация страховых случаев, обращения и изменение контактов.
Голосовой канал реализован через сообщения Telegram; веб-интерфейс и телефония не реализованы.
После передачи контекста бот явно говорит, что живой оператор не подключается.
«Да, подключайся» не возобновляет старый сценарий и не повторяет передачу. Старые
вопросы сохраняются; вернуться можно явно: «Вернёмся к предыдущему вопросу».

## Пакетная оценка маршрутизатора

Скрипт `src/main_router.py` выбирает сценарии обслуживания для реплик на русском,
казахском и смешанном языке. Он читает 40 бизнес-сценариев и 3 системных намерения
из `data/scenarios.json`, обрабатывает 104 реплики из `data/dev_utterances.json`
и сохраняет `predictions.json` в корне проекта.

Используется OpenAI Chat Completions: строго `gpt-4o-mini`, температура `0.1`,
`response_format={"type": "json_object"}`. Каталог в промпте сжат до `scenario_id`,
`name`, `description`, `not_this_if`; отдельное правило задаёт приоритет срочных
обращений. Правила исключения применяются к каждой самостоятельной просьбе.
Дополнительные инструкции и четыре коротких примера на русском и казахском
различают намерения клиента, обстоятельства и последующие этапы обслуживания.
Эталонные ответы `expected` и ID реплик модели не передаются.

## Установка и запуск

Нужны Python 3.10+ и ключ OpenAI API с доступом к модели.
Команды выполняются из корня проекта:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

В `.env` укажите `OPENAI_API_KEY=ваш_ключ`, затем запустите:

```bash
python src/main_router.py
python data/evaluate.py predictions.json data/dev_utterances.json
```

В Windows для активации используйте `.venv\Scripts\Activate.ps1`,
а для копирования — `Copy-Item .env.example .env`.
Файл `.env` исключён из Git. Вместо него можно задать переменную окружения
`OPENAI_API_KEY`; она имеет приоритет. При обработке скрипт обращается к внешнему
OpenAI API и расходует его квоту. Сам скрипт можно запускать из любой рабочей папки.

Пример формата результата (иллюстрация, не измеренный результат):

```json
{"U001": ["SC01"], "U085": ["SC26", "SC29"]}
```

Оценщик выводит точность первого сценария (`primary_accuracy`), совпадение наборов
сценариев (`full_match`) и полноту нескольких намерений (`intent_recall`), включая
разбивку по языкам и типам реплик.

Результаты проверки текущего `predictions.json` на всех 104 репликах dev-набора.
Исходный прогон сохранён в `predictions.baseline.json` для сравнения:

| Метрика | Исходный промпт | Уточнённый промпт |
|---|---|---|
| Верный первый сценарий | 98 / 104 — 94,2% | 104 / 104 — 100% |
| Полное совпадение набора сценариев | 96 / 104 — 92,3% | 104 / 104 — 100% |
| Полнота намерений в запросах с несколькими просьбами | 96,2% | 100% |

Все ID реплик присутствуют, формат и ID сценариев корректны. В последнем прогоне
исправлены все 8 исходных ошибок, новых ошибок нет. С эталоном совпадают и наборы,
и порядок сценариев для всех 104 реплик.

Промпт уточнялся по ошибкам этого открытого dev-набора. Метрики относятся к одному
полному прогону итоговой версии; качество на скрытом наборе жюри ещё не проверено.
После нового запуска метрики нужно пересчитать.

Автоматические проверки без сети и API-ключа:

```bash
python -m unittest discover -s tests -v
```

Они проверяют загрузку данных, формат запросов, ошибки ответов, обработку всех
104 реплик с подставным API, сохранение результатов и диалоговые переходы:
идентификацию, выбор полиса, смену темы и языка, подтверждение, отказ и ошибки.
Эти проверки не измеряют точность живой модели в диалоге.

Регрессионные реплики для проверки приветствия и смены темы с настоящим API:

```bash
python src/chat_demo.py --script examples/dialog_regression.json --trace
```

Для независимых проверок разных клиентов используйте `/reset` между примерами.
Для проверки переключения темы внутри одного разговора `/reset` не нужен.

Проверка текущей версии: 75 локальных тестов без сети прошли. Отдельно выполнен
живой прогон `dialog_regression.json`: приветствие, уточнение пострадавших,
переключение с ДТП на добавление водителя и с казахского ДМС на русский спор о выплате.
Синтез и последующее распознавание коротких приветствий RU/KK через OpenAI прошли;
это тест синтетической записи, а не качества любого микрофона или произношения.
Полная проверка отправки и получения сообщений Telegram требует токена вашего бота.

Поведение после оператора можно проверить командой
`python src/chat_demo.py --script examples/handoff_regression.json --trace`.
После изменения кода остановите запущенный Telegram-процесс через `Ctrl+C` и снова
выполните `python src/telegram_bot.py`; уже запущенный процесс не подхватывает правки.

## Поведение при ошибках и ограничения

Отсутствующие файлы, неверная структура данных и отсутствие ключа приводят к
понятной ошибке и ненулевому коду завершения. Ошибки API, пустые или некорректные
ответы, неизвестные ID заменяются на `["SYS_UNCLEAR"]` с предупреждением.
Такие замены входят в итоговую оценку наравне с обычными предсказаниями.
Клиент использует тайм-аут 30 секунд и до двух повторов временных ошибок.
Результат записывается атомарно после обработки всего набора; при прерывании
промежуточный прогресс не сохраняется. При повторном успешном запуске файл заменяется.

Результат 100% относится к пакетному маршрутизатору на открытом dev-наборе,
а не ко всем возможным диалогам. В чате новый запрос требует отдельного извлечения
полей и выбора сценария; формулирование информационного ответа может требовать
ещё одного вызова модели. Голосовая задержка пока не измерена; низкая температура
не гарантирует одинаковых ответов при каждом запуске.

Полное описание кейса и данных: [data/README.ru.md](data/README.ru.md).
Сведения о компании и клиентах в наборе синтетические.
